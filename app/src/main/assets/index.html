  • Gruppenverwaltung, Index & Filter:
    • Eine Gruppe besteht aus Gruppenname und Kennung / Index, z.B. &Andyx:AX. Der Gruppenname ist die gut lesbare Anzeige; der Index ist die eindeutige interne Kennung.
    • Beim Erstellen einer neuen Gruppe wird als Index automatisch der erste Buchstabe des Gruppennamens vorgeschlagen. Der Vorschlag kann überschrieben werden, z.B. mit A, AX oder A-X.
    • Der vollständige Index muss eindeutig sein. Schon während der Eingabe wird angezeigt, ob der Index frei oder bereits vergeben ist. Neue Indizes der Form A1, A2 usw. sind für ältere Listen reserviert.
    • Über ☰ → ✏️ Gruppen verwalten kann eine bestehende Gruppe ausgewählt und sowohl der Name als auch der Index geändert werden. Die Änderung wird auf die zugehörigen Barcodes und die gespeicherten gruppenbezogenen Einstellungen übernommen.
    • Kompatibilität mit alten Listen: ältere Gruppenkennungen wie A1 oder A2 werden weiterhin erkannt. Die alte Positionszahl wird für die Gruppenzuordnung ignoriert; unveränderte Alt-Einträge bleiben beim Bearbeiten erhalten. Dadurch können alte Importlisten weiterhin verwendet werden.
    • Das Gruppen-Dropdown wird aus den vorhandenen Gruppen aufgebaut. Ist eine Gruppe ausgewählt, kann innerhalb dieser Gruppe mit ↑/↓ eine eigene Reihenfolge gespeichert werden. Ohne Auswahl werden alle Gruppen angezeigt.

  • Erweiterte Barcode-Syntax (Spezialbefehle in eckigen Klammern):
    • Pw:dd.mm.yyyy (z.B. Pw:13.05.2025): Legt ein spezifisches Referenzdatum für den Barcode fest. Die 90-Tage-Ablauffrist wird ab diesem Datum berechnet. Dies ist nützlich, um ein genaues Ablaufdatum zu definieren, das von der automatischen Berechnung (aktuelles Datum + konfigurierte Tage) abweicht.
    • P:M:id:[@] (z.B. P:M:123:@): Definiert den Barcode als Master. Er kann sich mit Slave-Barcodes über eine gemeinsame 'id' koppeln. Das optionale '@'-Symbol am Ende bewirkt, dass dieser Barcode das Haupt-Verfallsdatum (wie im oberen Bereich der App angezeigt) einblendet.
    • P:S:id (z.B. P:S:123): Definiert den Barcode als Slave. Er ist einem Master-Barcode mit derselben 'id' zugeordnet und zeigt selbst kein Verfallsdatum an. Nützlich für verbundene Barcodes ohne redundante Datumsanzeige.
    • *:+ / *:- (z.B. *:+ oder *:-): Dient als Umschalter für Barcodes innerhalb einer Gruppe. Je nach Zustand (+ oder -) können zugehörige Barcodes in der Hauptansicht z.B. ein- oder ausgeblendet werden. Die genaue Funktion hängt von der Gruppenkonfiguration ab.
    • &Gruppe:Index (z.B. &Andyx:AX oder &Saal:S): Weist den Barcode einer benannten 'Gruppe' (z.B. "Andyx", "Saal") mit einem eindeutigen 'Index' (z.B. "AX", "S") zu. Dies ermöglicht das Filtern und Sortieren von Barcodes sowie gruppenspezifische Aktionen. Das & ist wichtig.
    • # (Rautezeichen): Versteckt den Barcode. Wenn dieses Zeichen innerhalb der eckigen Klammern steht (z.B. [#] oder [P:M:123,@,#]), wird der Barcode standardmäßig nicht in der Liste angezeigt, kann aber über eine spezielle Option im Menü wieder sichtbar gemacht werden.
    • Hinweis: Alle diese Spezialbefehle werden im Bezeichnungsteil des Barcodes nach einem Schrägstrich (/) und innerhalb von eckigen Klammern [...] eingegeben. Mehrere Befehle können mit Kommas getrennt werden (z.B. Code123/Label [P:M:123:@, &Gruppe:AX, #]).
  • Sonderzeichen im Barcode-Teil (vor dem Slash /):
    • ␠ = Leerzeichen (Space)
    • ␉ = Tabulator (HT / TAB)
    • ␍ = Enter (CR / Carriage Return)
    • ␊ = Zeilenumbruch (LF / Line Feed)
    • ␍␊ = Windows-Enter (CRLF)
    • Die sichtbaren Zeichen werden im Editor nur als gut erkennbare Platzhalter dargestellt. Beim Speichern/Scannen werden daraus die echten Steuerzeichen. Die Sonderzeichen gehören in den Barcode-Teil vor dem Schrägstrich /.
    • Beispiele:
      • 20␍535175/Torsionsring EQ6 Behälter
      • 20␉535175/Torsionsring EQ6 Behälter
      • 20␠535175/Torsionsring EQ6 Behälter
